# 麦麦：点餐页面里的悬浮对话伙伴

2026-10-25 更新。本稿取代此前以点餐功能页为中心的方案。用户明确：麦麦是可沟通的人物；功能通过对话完成。当前交付为可点击的交互设计演示，尚未接入真正的 AI 或实时 MCP。

## 已确认的设计依据

| 用户选择 | 可观察的设计行为 |
| --- | --- |
| 以未来点餐页面中的悬浮麦麦为目标 | 麦麦固定在点餐场景右下方，点击人物本身进入交流；背景只承担嵌入场景示意 |
| 对话紧贴麦麦身旁，可收起且保留记录 | 对话窗在人物上方展开，尾部指向人物；无全屏遮罩；收起后重开仍是同一段会话 |
| 简短文字与商品卡片，可选且继续聊着改 | 商品、门店、餐单确认都作为回复内容，不跳到预算表单、优惠页或菜单页 |
| 套餐、单点都使用圆形商品图 | 所有商品图共用圆形容器，优先完整呈现餐品；缺图退到标注的示意图 |
| 全像素游戏风 | 角色、窗框、硬投影与方形控件形成像素语言；中文正文保持可读；商品图按用户要求为圆形 |
| 预算配餐、优惠、门店菜单三个功能都要 | 三种任务共享对话、门店、预算与餐单上下文，不建立三套功能导航 |
| 正常友好交流，偶尔海鸥薯条梗 | 先准确回答任务，再偶尔插入陪伴语；金额、失败原因和订单状态不用玩梗表达 |

设计目标是让人感觉“正在和麦麦沟通”。背景菜单是验证嵌入效果的布景；麦麦不是打开业务页面的按钮。未来官方点餐页面嵌入仍需合作；现有 MCP 不提供官方页面修改权限。

## 布局与视觉

```text
点餐页面（背景，正常可见与滚动）
                     ┌───────────────┐
                     │ 麦麦       收起│
                     │ 当前店 / 预算  │
                     │ 你：30元配一餐 │
                     │ 麦麦：在哪取餐？│
                     │ 圆图 + 商品卡片│
                     │ 正在核对价格… │
                     │ 输入消息   发送│
                     └───────────┬───┘
                                 麦麦
                            海鸥在旁边
```

番茄红 `#bf343c`、薯条黄 `#ffd447`、纸袋米白 `#fff5d6`、深可可 `#4c292c`、海鸥灰蓝 `#d5e7ec`。沿用已有角色和四段海鸥小剧场，不重画人物。正文采用微软雅黑 / 苹方系统字体。背景内容视觉安静，主要记忆点是人物与对话框的关系，不使用大幅助手宣传区。

窄屏时对话框占可用宽度，人物仍在其下方，消息区域独立滚动；键盘或横屏压缩可见高度时，人物缩小、快捷问题收起，优先保留输入和消息。提供减少动态选项，动画状态都有文字等价信息。实际手机键盘与浏览器缩放仍需设备验收。

## 五类界面部件

1. 悬浮人物：待机 / 收到消息 / 处理 / 回复完成 / 失败的动作；人物本身可点击，支持键盘聚焦。
2. 贴身对话窗：麦麦名字、处理状态、门店与预算摘要、会话记录、输入、发送、收起。
3. 回复卡片：门店选择卡、圆图套餐卡、圆图单品卡、活动条件卡、餐单组成与确认卡。卡片是可选的快捷操作，文字输入也能继续任务。
4. 处理状态：正在整理需求、查询菜单、核对整单价格；可停止。当前演示的状态明确带“演示”，不声称在请求真实业务。
5. 恢复提示：无匹配、未知问题、失败、停止、待重新核价、此前餐单已修改。保留已有输入条件和草稿。

聊天不是模态弹窗，不覆盖整页遮罩。收起按钮 / Escape / 再点人物可以收起；收起后焦点返回人物。重新打开聚焦输入，历史消息不清空。处理期间收起不会停止任务；完成后人物旁显示新回复提醒。主动按“停止”才中止当前回复。

## 三条对话流程

预算：用户“30元，要汉堡和无糖饮料” → 麦麦追问取餐位置 → 回复门店卡，用户确认 → 查询与核价 → 在消息中比较最多三份完整套餐 → 用户“选第二份” → 回复餐单草稿 → 用户“饮料换大杯” → 旧价失效 → 完整重新核价 → 回复新餐单 → 用户“看看确认单” → 对话内确认卡，明确尚未下单。

门店 / 菜单：用户指定城市或地标 → 麦麦回复门店结果，等待选择 → 沿用门店查询菜单 → 回复圆形套餐 / 单品卡片 → 用户看组成或按预算搭配。用户换店后，正式版保留可读草稿但使原报价失效，再查新店菜单与价格。原型只有一间历史测试店，不虚构第二间店。

优惠：用户“最近有什么活动” / “我有什么券” → 根据问题查询公共活动或当前已授权账户 → 回复时间、适用范围与条件 → 用户要求用券配餐时再完整核价。正式版不能把未拥有券、宣传价或测试账户券当成当前用户优惠。原型只展示优惠回复的位置与条件结构，尚未执行真实查询。

用户可以随时插入闲聊，再回到原餐单；上下文仍在。正式实现应由模型理解多轮语义并调用工具，不以固定关键词脚本替代最终能力。

## 状态、数据与恢复约定

| 状态 | 用户可见反馈 | 保留与恢复 |
| --- | --- | --- |
| 收起 / 展开 | 点击人物出现贴身对话，收起仍可见人物 | 本次页面内消息、门店、预算、草稿全部保留；刷新清空，页面明示 |
| 处理进行中 | 人物认真处理，显示当前步骤与停止按钮 | 继续编辑下一条输入；阅读历史；避免重复提交 |
| 收起期间收到回复 | 人物旁出现“有新回复” | 重开可查看，后台不另开功能页 |
| 主动停止 | 显示停止提示，可再试一次 | 已完成步骤和草稿不回滚成假成功；修改中的价格保持待核价 |
| 修改套餐 | 旧总价失效，显示“待重新核价” | 历史消息标注“此前记录，后续已修改”，旧确认单复制操作禁用 |
| 核价成功 | 完整选择、历史 / 实时报价属性、时间、预算差额 | 原型读取历史匹配记录；正式版以对应请求的业务成功为准 |
| 错误 / 无匹配 | 具体说明限制，允许修改问题或重试 | 不补造餐品、价格、门店或优惠；保留原草稿 |
| 确认餐单 | 完整选择、店、取餐方式、价格来源、优惠状态 | 只是草稿，不创建订单、领券、兑换或付款 |

当前页面不写入浏览器持久存储，不上传聊天内容，不提供凭证输入。正式多用户版本的账户授权、会话保存时长与清空操作由后续实现确认，不能让所有用户共用开发账户。

## 图片契约

菜单与餐品详情的 MCP schema 均有 `image` 字段。前端商品对象接受可选 `image` HTTPS 地址；显示时用圆形容器和 `object-fit: contain`，图片本身保持原貌。链接无效或失败时显示明确的缺图状态，保留商品名与餐单。所有套餐和单品共用此组件。

2026-10-25 已通过当前会话的 MCP 实际取得 7 个商品原图：两份套餐、吉士汉堡包、麦香鸡、中薯条、中杯与大杯无糖可乐。当前页面按商品编码使用接口原始 HTTPS 地址，全部保持圆形容器与完整图片。旧记录中的龙焰套餐和单品当前查询不到，显示“暂无原图”，不借用其他餐品照片；加载失败显示“图片未加载”。此前的三张本地 SVG 不再用于当前商品显示。图片采集与历史整单报价独立记录，详见 `product-images.snapshot.json`。素材使用范围按赛事与服务条款核对，不能从字段存在推断任意商业授权。

## 实现边界与后续接入

- `mobile-ordering-preview.html/css/js`：悬浮角色、贴身对话、圆图卡片、异步演示状态、停止与重试、减少动态、视口压缩处理。
- `maimai-conversation.js`：有限的对话演示状态机，支持上述可演示的多轮路径；不是语言模型。
- `mobile-ordering-model.js`：分单位金额、历史核价、修改失效与预算过滤逻辑。
- `mobile-ordering-data.js`：2026-10-24 的三份已验证套餐与一组饮料替换；非当前价格与可售状态。单品不编造独立售价。

正式接入要替换前端 `send` 中的演示等待与脚本响应，由后端模型提供会话、工具调用与结构化结果。MCP Token 仅留在后端。需要返回文字、卡片、业务上下文、逐步处理状态及可停止的请求标识；业务失败不能发成成功回复。这里记录的是后续接口需求，不代表已有 AI 服务端或流式对话接口。

正式状态事件需要区分：接到消息、澄清需求、工具执行中、部分成功、工具失败、回复完成、用户停止。海鸥成功偷吃只由成功业务事件触发，失败不播放成功；不改变餐单薯条数量与金额。当前演示仅在成功展示已核价历史卡片后播放一次。

动作扩展已加入八组共 32 帧：倾听、说话、翻找、算价、炸薯条、吃薯条、打瞌睡和摸头回应。`maimai-motion.js` 负责处理优先级、一次性反馈和低频陪伴；长按人物约 550ms 或消息“摸摸你”可触发回应。其余小互动也可直接在聊天中提出，不改变餐单。减少动态显示静态关键帧，关闭自动彩蛋。全部 21 组动作可在 [动作画廊](motion-preview.html) 查看，具体时序与参考依据见 [动作设计](motion-design.md)。

## 验收与未验收

本次逻辑检查覆盖：追问门店后继续原预算、明确选择门店、选第二份再换杯、先失效后核价、中断后保持待核价、未知问题说明边界、排除项 / 人数 / 金额不制造假匹配、不伪造单点价格或账户券、草稿确认不代表下单。另验证忙碌状态优先、成功只庆祝一次、停止 / 失败清除庆祝、闲置彩蛋、减少动态，以及陪伴互动不修改餐单；与原金额模型合计 19 项测试通过。本轮再加入任务动作规划、回复分类和商品图对应检查，当前合计 25 项通过。

HTML 资源与脚本语法另行检查。当前会话的浏览器控制只暴露空的 MCP Apps 浏览器，无法进行实际界面截图或点击验收；不能把逻辑测试当成布局、手机键盘或真实 AI / MCP 验收。下一步评审点击人物后的窗口位置、阅读尺度与人物存在感；确认后实现实时对话与业务查询。
